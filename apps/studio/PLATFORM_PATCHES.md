# Platform patches

Changes made to the vendored fork (see `UPSTREAM.md`), one commit each, in order. To move to a new fork commit,
re-vendor, then `git cherry-pick` these commits (`git log --oneline -- apps/studio` lists them).

Platform code lives in new files under `apps/studio/platform/`; fork files only get small hooks.

| # | Commit subject | Files | Why |
|---|---|---|---|
| 1 | Studio: keep vendored code out of pnpm -r typecheck | `package.json` of apps/studio and vendor packages | The fork's own `tsc` is red (zod 3 schemas vs `@hookform/resolvers` types, e.g. `vendor/ui-patterns/src/Dialogs/TextConfirmModal.tsx`) and takes ~75 s; `next build` skips type errors (`ignoreBuildErrors`). Scripts renamed `typecheck:upstream`. |
| 2 | Studio: host build with a standalone runtime image | `next.config.js` (`outputFileTracingRoot`), new `build.sh`, `Dockerfile.platform`, `.gitignore` | Standalone output rooted at the monorepo (otherwise Next picks the highest lockfile, e.g. `~/package-lock.json`). `next build` runs on the host, the image only copies the output and installs sharp for the target platform. |
| 3 | Studio: trust the platform identity, guard every request | new `platform/identity.ts`, `platform/guard.ts`; hook in `proxy.ts` | Caddy sets `X-Platform-User/Role/Apps` from the control plane's forward auth, signed (`X-Platform-Signature`, HMAC with `PLATFORM_STUDIO_HEADER_SECRET`). The proxy answers 401 without a valid identity, 403 on a ref outside `X-Platform-Apps` (admins: any) and on fork features (bootstrap, import, project create/delete, failover, replicas, licence, functions folder...). |
| 4 | Studio: projects from the control plane, scoped to the request identity | new `platform/projects.ts`; hooks in `lib/api/apiWrapper.ts`, `lib/api/self-hosted/projectsStore.ts`, `instrumentation.ts`, `pages/api/platform/profile/index.ts` | Replaces `projects.json`: project configs are fetched from `GET $PLATFORM_CONTROL_PLANE_URL/internal/studio/projects` (bearer `PLATFORM_STUDIO_CONFIG_TOKEN`, 2 s cache in memory). Every API route runs in an AsyncLocalStorage context holding the verified identity; the store only returns that identity's projects (lists, org projects, lookups by ref) and refuses writes; no virtual "default" project. The health poller (failover) is off. The profile shows the platform user. |
| 5 | Studio: pg-meta proxy routes use the project's connection | `lib/api/self-hosted/pgMetaProxy.ts`, `lib/api/self-hosted/query.ts` | Fork bug (M0bis): `GET pg-meta/[ref]/tables|policies|...` ignored external projects (`db_host`) and hit pg-meta's default database. `getPgMetaProxyConfig` now sends `x-connection-encrypted` derived from the project, shared with `executeQuery`. Replaces the spike's `sed`. |
| 6 | Studio: Auth and Storage routes call the project's API | new `platform/projectApi.ts`; `pages/api/platform/auth/[ref]/*` (7 files), `pages/api/platform/storage/[ref]/**` (10 files), `pages/api/platform/projects/[ref]/api/rest.ts` | These routes used the global `SUPABASE_URL` / `SUPABASE_SERVICE_KEY`: a user created "in app1" landed in the default stack. They now use the project's `internal_url` (internal Caddy, `http://caddy:8180/<slug>`) and `service_key`. Same pattern in every file: one import, one line per handler. |
| 7 | Studio: stopped apps are read-only, with a banner | new `platform/stopped.ts`, `platform/StoppedBanner.tsx`; hooks in `components/layouts/ProjectLayout/index.tsx`, `lib/api/self-hosted/query.ts`, `platform/projects.ts` | The control plane reports a stopped app `ACTIVE_HEALTHY` (Studio skips its policies, publications... queries otherwise, though the database stays readable) with `platform_status: "stopped"`: a banner says the app is stopped, and a write refused by the read-only database (SQLSTATE 25006) gets a message naming the app instead of Postgres's. |
| 8 | Studio: no organization creation | `build.sh` (`NEXT_PUBLIC_DISABLED_FEATURES=organizations:create`) | Apps and their single organization come from the platform: the "New organization" buttons led to refused pages. |
| 9 | Studio: uploads through a same-origin TUS proxy | new `pages/api/platform/storage/[ref]/upload/resumable/[[...id]].ts`; `state/storage-explorer.tsx` | The storage explorer uploaded straight to the app's Storage with a "temporary" key that the fork's route serves as the project's permanent service key (refused by the platform's policy: `projects/<ref>` is read-only). The upload now goes to a Studio route that adds the service key server side and streams the TUS requests to the app (Location rewritten to the route): no key of the app in the browser, no CORS. |
| 10 | Studio: Sign out ends the platform session | new `platform/signOut.ts`; `components/interfaces/LocalDropdown.tsx` | The account menu's Sign out only cleared Studio's GoTrue client: the platform session cookie stayed. It now posts `/_platform/logout` and goes to the platform's login page. |
| 11 | Studio: no plan badge in the header | `components/layouts/AppLayout/OrganizationDropdown.tsx` | The single organization's plan ("Enterprise", from the self-hosted organizations store) means nothing on the platform. |
| 12 | Studio: no temporary key in the browser (folders, OAuth admin, Realtime Inspector) | new `platform/storageFolders.ts`, `platform/projectClient.ts`, `platform/authAdmin.ts`, `platform/oauthServer.ts`, `platform/realtimeToken.ts`, `platform/realtimeTokenRoute.ts`, `pages/api/platform/storage/[ref]/buckets/[id]/objects/placeholder.ts`, `pages/api/platform/auth/[ref]/gotrue/auth/v1/admin/[...path].ts`, `pages/api/platform/auth/[ref]/realtime-token.ts`; hooks in `state/storage-explorer.tsx`, `lib/project-supabase-client.ts`, `components/interfaces/Auth/OAuthApps/OAuthAppsList.tsx`, `components/interfaces/Realtime/Inspector/{Header,ChooseChannelPopover,RealtimeTokensPopover}.tsx` | The fork's "temporary" key is the project's permanent service key (refused by the policy). Empty folders: a Studio route creates the placeholder object with the service key. OAuth Server apps and custom providers: `createProjectSupabaseClient` points at a same-origin proxy of the app's GoTrue admin API (`oauth/clients*`, `custom-providers*` only; `custom:company`, the platform's company SSO, read-only; OAuth Server is off on the apps, shown as "not available on this platform"). Realtime Inspector: a 10-minute `service_role` JWT for the project only, minted by the control plane (`/internal/studio/realtime-token`), which holds the app's JWT secret. |
| 13 | Studio: Open app link in the header | new `platform/OpenAppButton.tsx`; hook in `components/layouts/Navigation/LayoutHeader/LayoutHeader.tsx` | Builders had no way to reach the running app from Studio. The button opens the project's `public_url` (`https://<app>.<domain>`, served by the control plane) in a new tab; a stopped app shows its maintenance page. |
