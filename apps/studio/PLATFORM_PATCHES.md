# Platform patches

Changes made to the vendored fork (see `UPSTREAM.md`), one commit each, in order. To move to a new fork commit,
re-vendor, then `git cherry-pick` these commits (`git log --oneline -- apps/studio` lists them).

Platform code lives in new files under `apps/studio/platform/`; fork files only get small hooks.

| # | Commit subject | Files | Why |
|---|---|---|---|
| 1 | Studio: keep vendored code out of pnpm -r typecheck | `package.json` of apps/studio and vendor packages | The fork's own `tsc` is red (zod 3 schemas vs `@hookform/resolvers` types, e.g. `vendor/ui-patterns/src/Dialogs/TextConfirmModal.tsx`) and takes ~75 s; `next build` skips type errors (`ignoreBuildErrors`). Scripts renamed `typecheck:upstream`. |
| 2 | Studio: host build with a standalone runtime image | `next.config.js` (`outputFileTracingRoot`), new `build.sh`, `Dockerfile.platform`, `.gitignore` | Standalone output rooted at the monorepo (otherwise Next picks the highest lockfile, e.g. `~/package-lock.json`). `next build` runs on the host, the image only copies the output and installs sharp for the target platform. |
| 3 | Studio: trust the platform identity, guard every request | new `platform/identity.ts`, `platform/guard.ts`; hook in `proxy.ts` | Caddy sets `X-Platform-User/Role/Apps` from the control plane's forward auth, signed (`X-Platform-Signature`, HMAC with `PLATFORM_STUDIO_HEADER_SECRET`). The proxy answers 401 without a valid identity, 403 on a ref outside `X-Platform-Apps` (admins: any) and on fork features (bootstrap, import, project create/delete, failover, replicas, licence, functions folder...). |
| 4 | Studio: projects from the control plane, scoped to the request identity | new `platform/projects.ts`; hooks in `lib/api/apiWrapper.ts`, `lib/api/self-hosted/projectsStore.ts`, `instrumentation.ts`, `pages/api/platform/profile/index.ts` | Replaces `projects.json`: project configs are fetched from `GET $PLATFORM_CONTROL_PLANE_URL/internal/studio/projects` (bearer `PLATFORM_STUDIO_CONFIG_TOKEN`, 2 s cache in memory). Every API route runs in an AsyncLocalStorage context holding the verified identity; the store only returns that identity's projects (lists, org projects, lookups by ref) and refuses writes; no virtual "default" project. The health poller (failover) is off. The profile shows the platform user. |
| 5 | Studio: pg-meta proxy routes use the project's connection | `lib/api/self-hosted/pgMetaProxy.ts`, `lib/api/self-hosted/query.ts` | Fork bug (M0bis): `GET pg-meta/[ref]/tables|policies|...` ignored external projects (`db_host`) and hit pg-meta's default database. `getPgMetaProxyConfig` now sends `x-connection-encrypted` derived from the project, shared with `executeQuery`. Replaces the spike's `sed`. |
| 6 | Studio: Auth and Storage routes call the project's API | new `platform/projectApi.ts`; `pages/api/platform/auth/[ref]/*` (7 files), `pages/api/platform/storage/[ref]/**` (10 files), `pages/api/platform/projects/[ref]/api/rest.ts` | These routes used the global `SUPABASE_URL` / `SUPABASE_SERVICE_KEY`: a user created "in app1" landed in the default stack. They now use the project's `internal_url` (internal Caddy, `http://caddy:8180/<slug>`) and `service_key`. Same pattern in every file: one import, one line per handler. |
